# 截图存放目录（日志采集手册）

`LOG-COLLECT.md` 正文刻意**不内嵌截图** —— 截图里必然带内网 IP、主机名、账号、
真实业务名与索引名，而本仓库是**公开仓库**，直接提交等于对外披露内网信息。

需要截图时，请放在本目录，并**先完成脱敏**。

## 命名与用途

| 文件名 | 该拍什么 | 建议放在手册哪一节 |
|---|---|---|
| `01-task-form.png` | 平台「新建采集任务」表单 | 5.3 新建采集任务 |
| `02-env-detect.png` | 「环境检测」结果与 warnings 列表 | 5.4 环境检测会告诉你什么 |
| `03-preview.png` | 「试跑」结果弹窗（样本 / 保留 / 被过滤） | 6.1 先试跑 |
| `04-dispatch-result.png` | 「下发结果」弹窗（成功或异常明细） | 6.2 下发 |
| `05-es-indices.png` | `_cat/indices` 输出，圈出你的索引那一行 | 6.4 验证数据真的进了 ES |
| `06-search.png` | 日志检索页出结果 | 6.5 回到平台检索 |

## 脱敏检查清单（提交前逐条过）

- [ ] 内网 IP 全部遮挡或替换（不要只糊一层浅色，要完全覆盖）
- [ ] 主机名遮挡
- [ ] 账号名遮挡（`root` 例外，可以留）
- [ ] 真实业务名 / 索引名遮挡或替换为 `myapp-log`
- [ ] 终端截图里的 SSH 命令、私钥路径遮挡
- [ ] 日志正文如有密码、token、手机号、身份证号 → 遮挡
- [ ] 弹窗标题里的任务名（往往含真实业务名）遮挡

## 如何插入到手册

在对应小节末尾加一行：

```markdown
![新建采集任务](docs/images/log-collect/01-task-form.png)
```

> 提示：GitHub 的 Markdown 支持仓库内的 PNG/SVG。若图片较大，
> 建议先压到 200 KB 以内再提交。
