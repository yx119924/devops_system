# XwOps 平台 内网部署文档（小白版）

> 目标：把当前运行在云服务器（YOUR_SERVER_IP）上的 XwOps 平台，完整迁移到**本地内网服务器**上运行。  
> 本手册每一步都给出**可以直接复制粘贴的命令**，跟着做即可。

根据你内网【是否已经有 MySQL / Redis】，选一条：

| 场景                     | 条件                                     | 读哪部分                              |

## 〇、先搞懂：这套系统是怎么跑的（30 秒）

这套系统是 **Docker 容器 + docker-compose 编排**，一共 5 个容器：

| 容器                | 作用                | 端口               | 说明               |
| ----------------- | ----------------- | ---------------- | ---------------- |
| `dvadmin3-web`    | 前端页面 + nginx 反向代理 | **8080**（对外唯一入口） | 别人访问系统就访问这个      |
| `dvadmin3-django` | 后端 API            | 8000             | 被 nginx 代理，不直接对外 |
| `dvadmin3-mysql`  | 数据库               | 3306             | 存所有业务数据          |
| `dvadmin3-redis`  | 缓存                | 6379             | 缓存 + Celery 消息队列 |
| `dvadmin3-celery` | 异步任务              | -                | 定时任务等            |

**两个关键认知（一定要理解）：**

1. **后端代码是「挂载」进容器的，不是打包进镜像的。**  
   也就是说，`dvadmin3-django` / `dvadmin3-celery` 这两个镜像里只有 Python 环境 + 依赖库，**真正的业务代码在宿主机 `backend/` 目录里**。  
   👉 所以迁移时，**不能只搬镜像**，必须把 `backend/` 代码目录、`docker_env/` 数据目录一起搬。
2. **前端是打包进镜像的。** `dvadmin3-web` 镜像里已经包含了编译好的前端页面，搬镜像就够。

### 你的迁移思路对不对？

你问的「直接 `docker save` → 新环境 `docker load` → 启动」，**思路对，但少了代码和数据**。完整做法是：

```
docker save 镜像  +  打包 backend/ 代码目录  +  打包 docker_env/ 数据目录
        ↓ 一起打成部署包
新服务器解压 → docker load 镜像 → docker compose up -d
```

本手册已经把这件事自动化成一个打包脚本，你在源服务器上跑一下脚本，就得到一个完整的部署包。

### 端口规划（内网）

| 端口   | 作用                | 是否对外开放             |
| ---- | ----------------- | ------------------ |
| 8080 | Web 界面（其他机器访问系统用） | ✅ 是                |
| 8000 | Django 后端直连（调试用）  | 可选                 |
| 3306 | MySQL             | ⚠️ 已按你要求开放，见下方安全提示 |
| 6379 | Redis             | ⚠️ 已按你要求开放，见下方安全提示 |

> ⚠️ **安全提示**：实际上，内网其他机器**只需要访问 8080 端口**就能用整个系统（8080 的 nginx 会自动代理到后端）。  
> MySQL(3306) 和 Redis(6379) 是内部组件，正常不需要被外部直连。你要求把 `127.0.0.1` 改成 `0.0.0.0` 我已经在 compose 里改好了，但如果后续确认没有外部直连需求，建议改回 `127.0.0.1` 更安全（改法见第七章）。

## 一、部署方式说明（为什么用 docker save/load）

| 方案                             | 做法                         | 优点                         | 缺点                                                                       |
| ------------------------------ | -------------------------- | -------------------------- | ------------------------------------------------------------------------ |
| **A. docker save/load（本手册采用）** | 导出镜像 tar + 打包代码/数据         | 新环境**不用联网装依赖**、不用重新编译，最快最稳 | 镜像包较大（约 2 GB）                                                            |
| B. 拷贝源码重新 build                | 新环境 `docker compose build` | 包体积小                       | 新环境要联网 `npm install` / `pip install`，且可能踩之前的坑（vant 版本、npm 崩溃、国内镜像源等），耗时长 |

**结论：用方案 A。** 这也是你直觉的做法，正确。

## 二、源服务器打包（在云服务器 YOUR_SERVER_IP 上操作）

### 第 1 步：把打包脚本上传到源服务器

打包脚本叫 `pack_deploy.sh`（本部署包里已附带）。用以下任一方式上传：

```bash
# 方式一：scp 上传（在你自己电脑上执行）
scp pack_deploy.sh root@YOUR_SERVER_IP:/opt/devops-platform/

# 方式二：直接登录服务器后创建
ssh root@YOUR_SERVER_IP
```

> 源服务器 SSH 密码：`YOUR_SSH_PASSWORD`（末尾有个点）

### 第 2 步：执行打包脚本

```bash
cd /opt/devops-platform
bash pack_deploy.sh
```

脚本会依次做这些事（每步都有中文提示）：

1. 停止 5 个业务容器（保证数据一致，打包期间系统短暂不可用，属正常）
2. `docker save` 导出 5 个镜像
3. 打包 `backend/` 代码目录
4. 打包 `docker_env/` 数据目录
5. 拷贝 `.env` 密码文件
6. 生成改造后的 `docker-compose.yml`
7. 自动恢复源服务器容器运行

### 第 3 步：拿到部署包

脚本最后会打印部署包位置，类似：

```
部署包位置：/tmp/xwops_deploy_20260901_083000.tar.gz
```

把这个文件下载到你自己电脑（中转），再传到新服务器：

```bash
# 下载到本地电脑
scp root@YOUR_SERVER_IP:/tmp/xwops_deploy_20260901_083000.tar.gz .

# 上传到新服务器（IP 换成你内网服务器的地址）
scp xwops_deploy_20260901_083000.tar.gz root@<新服务器IP>:/root/
```

## 四、新服务器部署（核心步骤）

### 第 1 步：解压部署包

```bash
# 进入家目录
cd /root

# 解压部署包（文件名换成你实际的）
tar xzf xwops_deploy_20260901_083000.tar.gz
```

解压后得到 `xwops_deploy/` 目录，里面有：

```
xwops_deploy/
├── images/            # 5 个镜像 tar 包
│   ├── web.tar
│   ├── django.tar
│   ├── celery.tar
│   ├── mysql.tar
│   └── redis.tar
├── backend.tar.gz     # 后端代码
├── docker_env.tar.gz  # nginx 配置 + MySQL/Redis 数据
├── docker-compose.yml # 编排文件（已改好）
└── .env               # 密码文件
```

### 第 2 步：建立项目目录并解压

```bash
# 建立项目目录（和源服务器一致，方便对照）
mkdir -p /opt/devops-platform
cd /opt/devops-platform

# 把代码和数据解压进来
tar xzf /root/xwops_deploy/backend.tar.gz
tar xzf /root/xwops_deploy/docker_env.tar.gz

# 拷贝编排文件和密码
cp /root/xwops_deploy/docker-compose.yml .
cp /root/xwops_deploy/.env .

# 创建日志目录（compose 里挂载用，必须先建）
mkdir -p logs/log
```

### 第 3 步：加载镜像（docker load）

```bash
cd /opt/devops-platform

# 逐个加载镜像
docker load -i /root/xwops_deploy/images/web.tar
docker load -i /root/xwops_deploy/images/django.tar
docker load -i /root/xwops_deploy/images/celery.tar
docker load -i /root/xwops_deploy/images/mysql.tar
docker load -i /root/xwops_deploy/images/redis.tar
```

每行会输出 `Loaded image: xxx` 表示加载成功。

### 第 4 步：修正数据目录权限（重要！）

MySQL 和 Redis 数据目录在容器内由特定用户（uid=999）持有，解压后属主可能变成 root，会导致启动失败。执行：

```bash
cd /opt/devops-platform
chown -R 999:999 docker_env/mysql/data
chown -R 999:999 docker_env/redis/data
```

### 第 5 步：启动服务

```bash
cd /opt/devops-platform
docker compose up -d
```

会看到 5 个容器依次启动。等待约 30~60 秒（MySQL 首次初始化需要点时间）。

### 第 6 步：确认服务正常

```bash
docker compose ps
```

预期输出：5 个容器 `STATUS` 都是 `Up`（running）。如果某个容器一直 `Restarting`，看第七章排查。

## 五、部署后配置（内网监控对接）

> 你没部署 Prometheus / Alertmanager（内网已有），所以需要把平台的「监控数据源地址」指向你内网已有的监控。
>
> **监控地址已不再写死在代码里**，统一改到 Web 页面的「数据源管理」里配置，改完即时生效，无需改代码、无需重启后端。

### 第 1 步：在页面配置 Prometheus / Alertmanager 地址

1. 浏览器登录平台（登录信息见下方第 3 步），进入左侧菜单 **监控告警 → 数据源管理**。
2. 该页面同时管理 Prometheus 和 Alertmanager 两类地址，每类各保留一条「启用」状态的记录即可。默认已预置两条占位记录（地址为 `127.0.0.1`），把它们改掉或直接新增：

| 名称 | 类型 | 监控地址 | 状态 |
| -- | -- | -- | -- |
| 内网 Prometheus | Prometheus | `http://<内网Prometheus的IP:端口>` | 启用 |
| 内网 Alertmanager | Alertmanager | `http://<内网Alertmanager的IP:端口>` | 启用 |

> 例如内网 Prometheus 是 `192.168.1.100:9090`，监控地址就填 `http://192.168.1.100:9090`；Alertmanager 是 `192.168.1.100:9093`，就填 `http://192.168.1.100:9093`。
>
> 保存后立即生效：告警规则同步、活跃告警查询、Alertmanager 静默/路由等都会从这里读取地址，不用再改 `backend` 代码。

### 第 2 步：内网 Alertmanager 配置 webhook（反向对接）

在你内网已有的 Alertmanager 配置文件里，把告警接收器的 webhook 指向新平台：

```yaml
receivers:
  - name: 'platform'
    webhook_configs:
      - url: 'http://<新平台服务器IP>:8000/api/alert/webhook/receiver/'
        send_resolved: true
```

> 这样内网 Prometheus 产生告警后，会推给内网 Alertmanager，再由 Alertmanager 回调新平台的 webhook，平台再分发到飞书/钉钉/企微/邮箱。

### 第 3 步：登录验证

> ⚠️ **先重置密码**：仓库里的初始化 SQL 出于安全已把 superadmin / admin / test 的密码哈希替换为占位符，导入后无法直接登录。请先在 django 容器内重置密码：

```bash
docker exec -it dvadmin3-django python reset_password.py superadmin 你的新密码
# 也可顺便给演示账号设密码（可选）：
# docker exec -it dvadmin3-django python reset_password.py admin 你的新密码
```

> 脚本 `reset_password.py` 在 `deploy/tools/` 下，需先放进 `backend/` 目录（或直接 `docker cp` 进容器）再执行。

然后浏览器访问：

```
http://<新服务器IP>:8080
```

| 项目 | 值                        |
| -- | ------------------------ |
| 账号 | `superadmin`             |
| 密码 | 上一步你刚重置的新密码 |

登录成功后，检查左侧菜单：资产管理、堡垒机、监控告警、日志管理都在，说明迁移完整。

## 七、常见问题排查

### Q1：某容器一直 Restarting / 起不来

```bash
# 看具体报错（把 容器名 换成 web/django/mysql/redis/celery）
docker logs dvadmin3-django --tail 50
```

常见原因：

- **MySQL 起不来**：数据目录权限不对 → 重新执行 `chown -R 999:999 docker_env/mysql/data`
- **django 起不来**：连不上数据库 → 确认 mysql 容器 `Up`，且 `.env` 里的 `MYSQL_PASSWORD` 和 `backend/conf/env.py` 里的密码一致
- **web 起不来**：my.conf 没挂载 → 确认 `docker_env/nginx/my.conf` 存在

### Q2：访问 8080 打不开

```bash
# 1. 确认容器在跑
docker compose ps

# 2. 确认端口监听
ss -lntp | grep 8080

# 3. 防火墙放行（Ubuntu 用 ufw）
ufw allow 8080/tcp
ufw reload
```

### Q3：想改回只允许本机访问 MySQL/Redis（更安全）

编辑 `docker-compose.yml`，把：

```yaml
- "3306:3306"    # 改成 → "127.0.0.1:3306:3306"
- "6379:6379"    # 改成 → "127.0.0.1:6379:6379"
```

然后：

```bash
docker compose up -d
```

### Q4：内网有 172.30.0.0/16 网段冲突

默认 docker 网络用的是 `172.30.0.0/16`。如果内网已有这个网段会冲突，需要改三处（都改成不冲突的网段，比如 `172.30.0.0/16`）：

1. `docker-compose.yml` 末尾的 `subnet`
2. `backend/conf/env.py` 里的 `DATABASE_HOST`（改成 mysql 的新 IP）和 `REDIS_HOST`
3. `docker_env/nginx/my.conf` 里的 `proxy_pass http://172.30.0.12:8000/`（改成 django 的新 IP）

改完重启：

```bash
docker compose down && docker compose up -d
```

### Q5：堡垒机 Web SSH 连不上 / 录像不能回放

- 录像文件在 `backend/media/`，确认这个目录被一起打包迁移了
- Web SSH 走 WebSocket，确认 nginx `my.conf` 里 `/api/` 的 `proxy_set_header Upgrade` 那几行还在（部署包里的 my.conf 已含）

### Q6：CentOS 服务器怎么装 Docker

```bash
yum install -y yum-utils
yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
```

## 八、场景 B：内网已有 MySQL / Redis（外接）

> 适用：你内网已经部署好 MySQL 和 Redis，不想（也不需要）再起这两个容器。
> 核心就三件事：① 数据导入内网 MySQL；② 后端改指向内网 MySQL/Redis；③ 用外接版 compose 启动。

### 8.1 准备：场景 B 专用文件

部署包里专门为场景 B 准备了：

| 文件                            | 用途                                       |
| ----------------------------- | ---------------------------------------- |
| `init/xwops_init.sql`         | 完整初始化 SQL（建库 + 60 张表 + 全部业务数据）             |
| `init/init_external.sh`       | 内网建库 + 导数据脚本（改 4 个配置就能跑）                  |
| `init/xwops_init_mysql8.sql`  | 仅 MySQL 8.0 原始版（含 utf8mb3/CHECK，一般用不上） |
| `docker-compose.external.yml` | 外接版编排文件（只有 web/django/celery 三个容器）        |

### 8.2 第一步：把数据导入内网 MySQL

把 `init/` 目录整个拷到**能访问内网 MySQL 的机器**上，改好脚本顶部的 4 个配置后执行：

```bash
vi init_external.sh   # 改 MYSQL_HOST / 端口 / 管理员账号 / 密码
bash init_external.sh
```

等价的手动命令（不用脚本也行）：

```bash
# 1) 建库
mysql -h<内网MySQL地址> -uroot -p -e "CREATE DATABASE IF NOT EXISTS django-vue3-admin DEFAULT CHARACTER SET utf8 COLLATE utf8_general_ci;"

# 2) 导数据（--default-character-set 必须加，否则中文乱码）
mysql -h<内网MySQL地址> -uroot -p --default-character-set=utf8mb4 django-vue3-admin < xwops_init.sql
```

> **中文乱码防护**：导入时必须带 `--default-character-set=utf8mb4`，这是最容易踩的坑。
>
> **版本兼容**：`xwops_init.sql` 已做 5.7/8.0 兼容处理（utf8mb3→utf8、去掉 8.0 的 CHECK 约束），
> 你的内网 MySQL 无论是 5.7 还是 8.0 都能直接导。

### 8.3 第二步：给后端建一个连接账号（可选但推荐）

在内网 MySQL 上（用管理员账号登录后）执行：

```sql
CREATE USER 'xwops'@'%' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON `django-vue3-admin`.* TO 'xwops'@'%';
FLUSH PRIVILEGES;
```

> 也可以直接用管理员账号（root）连接，但生产环境建议单独建账号。

### 8.4 第三步：新服务器部署（跳过 mysql/redis 容器）

场景 B 只需起 3 个容器（web + django + celery），步骤和第四章基本一样，差别两点：

**① 用外接版 compose：**

```bash
cd /opt/devops-platform
cp /root/xwops_deploy/docker-compose.external.yml ./docker-compose.yml
```

**② 改 `backend/conf/env.py` 的连接信息（关键！）：**

```bash
vi backend/conf/env.py
```

把下面 4 处改成你内网的 MySQL / Redis 地址和密码：

| 配置项                | 原值（源服务器）             | 改成                        |
| ------------------- | --------------------- | ------------------------- |
| `DATABASE_HOST`     | `172.30.0.13`         | 内网 MySQL 地址（如 `192.168.1.100`） |
| `DATABASE_PASSWORD` | `YOUR_MYSQL_PASSWORD`  | 内网 MySQL 密码               |
| `REDIS_HOST`        | `172.30.0.15`         | 内网 Redis 地址               |
| `REDIS_PASSWORD`    | `YOUR_REDIS_PASSWORD`        | 内网 Redis 密码               |

> `DATABASE_USER` 默认 `root`，若 8.3 建了专用账号则改成那个账号名。
>
> **Redis 不用导数据**：Redis 在这里只是缓存 + Celery 任务队列，数据可自动重建，内网 Redis 直接用即可。
> 注意别和内网 Redis 其他业务冲突——系统默认用 `REDIS_DB=1`（缓存）和 `CELERY_BROKER_DB=3`（任务队列）。

改完启动：

```bash
docker compose up -d
docker compose ps
```

预期只有 3 个容器 `Up`（web/django/celery），没有 mysql/redis。

### 8.5 关键坑：MySQL/Redis 装在「宿主机本机」怎么办？

如果内网 MySQL/Redis 是**装在这台新服务器本机**（不是独立机器），容器访问它不能用 `127.0.0.1`（容器里的 127.0.0.1 是容器自己）。两种解法：

**解法一（推荐）**：env.py 里填**宿主机的内网 IP**（如 `192.168.1.10`，用 `ip addr` 查），别填 `127.0.0.1`。

**解法二**：若 MySQL/Redis 只监听 127.0.0.1 且不想改监听地址，在 compose 的 django/celery 服务里加：

```yaml
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

然后 env.py 里 `DATABASE_HOST = 'host.docker.internal'`、`REDIS_HOST = 'host.docker.internal'`。

> 同时确认内网 MySQL/Redis 的监听是 `0.0.0.0` 而不是 `127.0.0.1`，否则外部（含容器）连不进来。
