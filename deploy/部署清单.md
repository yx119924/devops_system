# XwOps 平台 - 部署文件清单

> 说明：这套系统「后端代码是挂载进容器的，不是打进镜像的」，所以部署包必须同时包含 **镜像 + 代码目录 + 数据目录** 三部分，缺一不可。

## 一、镜像（5 个）

| 镜像名 | 体积 | 用途 | 来源 |
|--------|------|------|------|
| `devops-platform-dvadmin3-web:latest` | 112 MB | 前端（nginx 静态服务，已含编译后的页面） | 自建（docker save） |
| `devops-platform-dvadmin3-django:latest` | 990 MB | 后端 Django 运行环境（含 Python 依赖，**不含业务代码**） | 自建（docker save） |
| `devops-platform-dvadmin3-celery:latest` | 979 MB | Celery 异步任务运行环境（同上） | 自建（docker save） |
| `mysql:8.0` | 1.1 GB | 数据库 | 官方镜像（docker save 或新环境 pull） |
| `redis:6.2.6-alpine` | 46 MB | 缓存 | 官方镜像（docker save 或新环境 pull） |

> 5 个镜像已由 `pack_deploy.sh` 统一 `docker save` 成 tar 包，放进部署包的 `images/` 目录。

## 二、代码 / 配置目录

| 目录 / 文件 | 用途 | 是否必须 |
|------------|------|---------|
| `backend/` | 后端全部业务代码（挂载进 django/celery 容器） | ✅ 必须 |
| `backend/media/` | 会话录像等媒体文件（堡垒机回放依赖） | ✅ 必须 |
| `backend/conf/env.py` | 数据库/Redis/加密密钥配置 | ✅ 必须 |
| `docker_env/nginx/my.conf` | nginx 反向代理配置 | ✅ 必须 |
| `docker_env/mysql/` | MySQL 数据 + 配置（`data/` 是业务数据） | ✅ 必须 |
| `docker_env/redis/` | Redis 数据 + 配置（`data/` + `redis.conf`） | ✅ 必须 |
| `docker_env/{django,celery,web}/Dockerfile` | 镜像构建文件（image 化后不 build，保留备重建） | 建议保留 |
| `docker-compose.yml` | 编排文件（已改造为 image 版） | ✅ 必须 |
| `.env` | 数据库/Redis 密码 | ✅ 必须 |

## 三、数据（已包含在上面目录内）

- **MySQL 业务数据**：`docker_env/mysql/data/`（全部业务表 + 菜单 + 用户 + 告警规则等）
- **Redis 数据**：`docker_env/redis/data/`（appendonly 持久化文件）
- **会话录像**：`backend/media/`（堡垒机 Web SSH 录像回放文件）

## 四、不部署的组件

| 组件 | 原因 |
|------|------|
| Prometheus | 内网已有，不部署 |
| Alertmanager | 内网已有，不部署 |
| node-exporter | 内网已有，不部署 |

> 监控相关只需要在部署后，把「数据源地址」改成内网已有的 Prometheus / Alertmanager 地址即可（见部署文档第五章）。

## 五、部署后必须修改的配置（内网地址）

> 监控地址**已不再硬编码在代码里**，统一在 Web 页面 **监控告警 → 数据源管理** 里配置（改完即时生效，无需改代码）。下面是部署后要改的点：

| 位置 | 原值 | 需改成 |
|------|------|--------|
| 数据源管理页（Prometheus） | `http://172.30.0.16:9090`（占位） | 内网 Prometheus 地址 |
| 数据源管理页（Alertmanager） | `http://172.30.0.18:9093`（占位） | 内网 Alertmanager 地址 |
| 内网 Alertmanager 的 webhook | （无） | 指向新平台 `http://<新平台IP>:8000/api/alert/webhook/receiver/` |

## 六、登录信息（随数据迁移）

> ⚠️ 初始化 SQL 出于安全，已把 `superadmin` / `admin` / `test` 三个账号的密码哈希替换为占位符，**导入后这三个账号都无法登录**，必须先重置密码。

| 项目 | 值 |
|------|-----|
| 访问地址 | `http://<新服务器IP>:8080` |
| 账号 | `superadmin`（另有 `admin` / `test` 演示账号） |
| 首次登录 | 导入数据后，在 django 容器内执行 `python reset_password.py superadmin 你的新密码`（脚本见 `tools/reset_password.py`） |

## 七、场景 B：内网已有 MySQL / Redis（外接）

> 若内网已经部署好 MySQL 和 Redis，则**不需要**起 `mysql`/`redis` 两个容器，也不用迁移 `docker_env/mysql/`、`docker_env/redis/` 数据目录。

**场景 B 专用文件：**

| 文件 | 用途 |
|------|------|
| `init/xwops_init.sql` | 初始化 SQL（建库 `django-vue3-admin` + 60 张表 + 全部业务数据，5.7/8.0 通用，已脱敏） |
| `init/init_external.sh` | 内网建库 + 导数据脚本 |
| `docker-compose.external.yml` | 外接版编排（仅 web/django/celery 三容器） |
| `tools/reset_password.py` | 导入后重置 superadmin/admin/test 密码的脚本 |

**场景 B 部署后需改 `backend/conf/env.py`（区别于场景 A）：**

| 配置项 | 原值 | 改成 |
|--------|------|------|
| `DATABASE_HOST` | `172.30.0.13` | 内网 MySQL 地址 |
| `DATABASE_PASSWORD` | `YOUR_MYSQL_PASSWORD` | 内网 MySQL 密码 |
| `DATABASE_USER` | `root` | 内网 MySQL 连接账号（可建专用账号） |
| `REDIS_HOST` | `172.30.0.15` | 内网 Redis 地址 |
| `REDIS_PASSWORD` | `YOUR_REDIS_PASSWORD` | 内网 Redis 密码 |

> **Redis 不用导数据**（仅缓存 + Celery broker，可自动重建）。注意 DB 号：缓存 `REDIS_DB=1`、任务队列 `CELERY_BROKER_DB=3`，避免与内网 Redis 其他业务冲突。

> 完整步骤见《部署文档.md》第八章。
